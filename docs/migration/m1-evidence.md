## Воспроизводимая команда

Из корня **нового** репозитория, где `../source-audit` и `../ludory-audit` — независимые checkouts с указанными Git objects:

```sh
node tools/m1-inventory.mjs --source ../source-audit --ludory ../ludory-audit --output docs/migration/m1-inventory.json
```

Наблюдаемый выход: `fileCount=954` и `fileCount=2721`, exit 0. Результат не содержит локальных абсолютных путей, timestamps, байтов медиа или секретов. Каждый файл представлен ‎`path`, `mode`, `type`, Git object ID; итог сортируется по UTF-8 bytes. Для повторения без переписывания уже утверждённого манифеста следует вывести JSON во временный путь и сравнить SHA-256.

Проверены две независимые инварианты:

- сумма `groupCounts` равна числу `files` (954, 2721);
- файлы в каждом репозитории уникальны и строго упорядочены по UTF-8 байтам.

После записи повторно выполнили тот же CLI с новым output-файлом; `cmp` исходного и повторного JSON завершился с кодом 0 (байтовое совпадение). `node --check tools/m1-inventory.mjs`, `npm run test:m1` и полный `npm test` также вернули код 0. `npm` вывел только предупреждение о будущей поддержке конфигурационного ключа `http-proxy`, не связанное с тестами M1.

На момент первой записи ‎`npm run test:m1` и отдельный ‎`node --test tests/m1-inventory.test.mjs` завершились **5/5 PASS, 0 FAIL**. После независимого review добавлены проверки отсутствия автоматической догрузки в promisor partial clone, отказа на invalid UTF-8 и сохранности целевого файла при ошибке `rename`: итоговый набор **8/8 PASS, 0 FAIL**. Git child processes теперь принудительно используют `GIT_NO_LAZY_FETCH=1`; если нужного объекта нет в checkout, команда завершается ошибкой, не меняя Git object database.
