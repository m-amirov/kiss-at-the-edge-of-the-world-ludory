# M1 — Проектное решение о переносе «Поцелуя на краю света»

Дата: 2026-11-03. Статус: утверждено пользователем в диалоге; реализация M1 отдельно проверяется по PR.

## Цель

Перенести авторскую романтическую визуальную новеллу в новый независимый репозиторий как нативную игру Ludory, сохранив литературный канон и наблюдаемые последствия выборов. Исходный проект является только read-only источником. Старые CEOS/Starter Kit и историю их прогонов не переносим.

## Подтверждённые источники

- Исходная игра `m-amirov/kiss-at-the-edge-of-the-world`, зафиксированный HEAD `1e775f1fcd5269b2574b5a120a1f4f6f716ebb8c`.
- Ludory `m-amirov/ludory`, зафиксированный HEAD `0d034f1ab7e559b07080c00f6386a453e0e398b2`.
- Нормативная сюжетная иерархия: `PROJECT_RULES.md` → `docs/CONCEPT_CANON.md` → `docs/SEASON_1_STORY_ARCHITECTURE.md`, `docs/SEASON_1_SCENE_MATRIX.md`, `docs/SEASON_1_CHOICE_ARCHITECTURE.md`, `docs/ROMANCE_ROUTE_ARCHITECTURE.md` → рукопись `content/`.
- Документация может быть исторической: утверждения о том, что эпизоды 7–10 не написаны, конфликтуют с наличием отдельных файлов. Инвентаризация не считает наличие файла доказательством завершённой интеграции или утверждённого финала.

## Продуктовые инварианты

1. Новый сезон: 10 эпизодов, 21 день в Исландии; Алиса, Эрик, Ник, Дамир; три романтических маршрута и один самостоятельный.
2. Единственный route lock — осознанный выбор в S26; выбор одного из четырёх вечеров S18–S21 не фиксирует партнёра.
3. Выборы имеют наблюдаемые последствия; история не превращается в детектив/мистику и не заменяется старой 12-эпизодной демоверсией `src/season-data.js`.
4. Русский язык в первой версии; готовность английской локализации проверяется отдельно.
5. Портретный мобильный и широкий desktop интерфейсы, Back/save/reload, музыка и локальные медиа; существующие сохранения не импортируются до отдельной схемы совместимости.
6. Локальные цели сборки: Yandex Games и VK Games. Публикация, модерация на реальных площадках и релизная готовность не входят в текущую авторизацию.

## Архитектура

- Новая игра создаётся только через профиль/шаблон `narrative-interactive` Ludory Studio после read-only preview.
- Сюжет преобразуется в проверяемый `@ludory/narrative` graph/catalog с явными state effects, route locks и локализованными репликами; поэпизодные модули разделены.
- Интерфейс строится на `@ludory/runtime-narrative`; платформа изолирована в Yandex/VK Connect.
- Изображения, музыка и шрифты копируются только после сохранения происхождения, проверки целостности и правил экспортёра. Неизвестные права остаются блокером релизного допуска.
- Нативный экспорт двух платформ сейчас доступен через programmatic Studio API, а не универсальный `adopt`/CLI-экспорт. Он ограничивает допустимые HTML/CSS и asset roots; это проверяется на M2, прежде чем переносить всё оформление.

## Этапы

- **M1**: точные git-SHA, read-only инвентаризация файлов, классификация канона/прототипа, матрица паритета, оценка технических рисков. Никакого импорта.
- **M2**: нативный проект Ludory и один вертикальный срез с настоящим story graph, Back/save/reload и портретным UI.
- **M3**: перенос 10 эпизодов, блокировок маршрутов, условий и всех финалов по сценам с regression tests.
- **M4**: перенос и проверка медиа, аудио, локализации и интерактивности.
- **M5**: сценарная, визуальная, мобильная и state/save приёмка.
- **M6**: две локальные платформенные ZIP-сборки, хеши, контракты SDK и симуляция QA, без публикации.

## Подходы

- **А — чистый перенос** (выбран пользователем): новая архитектура Ludory и перенос канонического контента; требует отдельного адаптера данных, но исключает наследование прежней инфраструктуры.
- **Б — адаптация старого проекта** (отклонён): быстрее старт, но сохраняет старый runtime, его состояния и Starter Kit зависимости.

## M1 — вне объёма

Не запускать legacy миграцию с `--apply`, не изменять исходную игру, не копировать ассеты/историю прогонов, не публиковать, не обещать паритет или совместимость сохранений без проверок.

## Риски и критерии завершения M1

- Смешение исторического и утверждённого канона → матрица отмечает source-of-truth для каждого сюжетного слоя.
- Текст есть, playable реализации нет → отдельно фиксировать authored/integrated/verified.
- Несогласованные state-поля/финалы → не маппить автоматически; описать решения для M3.
- Ассеты крупные/права неясны → реестр без переноса байтов до M4.
- Export API и шаблон имеют ограничения → M2 планирует вертикальный срез до массового переноса.

M1 завершён только когда зафиксирована полная проверяемая git-tree инвентаризация обоих репозиториев, подготовлена матрица канона и миграционных блокеров, а проверки инструмента инвентаризации наблюдаемо проходят. Материалы принимаются в отдельном PR; `main` не затрагивается этим PR до проверки.
